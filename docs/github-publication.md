# GitHub 공개 안내

준비일: 2026-10-15. 이번 준비 대상은 소스 코드이며 저장소 생성·업로드·커밋·push는 하지 않았습니다.

## 공개할 내용

- `src/`, `scripts/`, `tests/`, `evals/`: 구현과 재현 도구, 공개 가능한 합성 기준 자료
- `README.md`, `docs/`: 설치·사용법, 설계, 측정 조건과 알려진 한계
- `LICENSE`, `licenses/`, `THIRD_PARTY_NOTICES.md`: MIT 원작자 고지와 제3자 출처
- 의존성 목록, pytest 설정, `.gitignore`
- `results/`의 검사된 합성 측정 결과. 실행 로그·사용자 파일 목록·색인 DB는 제외

## 사용할 소스

2026-10-15 사용자 요청에 따라 기존 작업 저장소의 13개 커밋 이력을 정리했습니다. 문서 blob 3개의 개인 경로를
`%USERPROFILE%`로 바꾸고, Windows TTS 시험 WAV 4개를 모든 커밋의 추적 대상에서 제거했습니다.
커밋 순서·작성 정보는 보존했고 커밋 해시는 바뀌었습니다. 원 이력은 `outputs/history-backup-20261015`에 비공개로 보관합니다.
정리된 Git 객체 전체에서 개인 경로·주요 자격증명 패턴을 다시 검사했고 현재 작업 파일은 보존했습니다.
기존 브랜치의 커밋되지 않은 최신 변경은 검토 후 별도 커밋해야 합니다. 이력 정리로 새 개발 커밋을 만들거나 push하지 않았습니다.

이력이 필요 없으면 `scripts/export_source.py`로 만든 최신 공개 스냅샷도 사용할 수 있습니다.
어느 경우에도 `outputs/`의 원 이력 백업·개인용 EXE·환경·설정·색인을 저장소에 추가하지 않습니다.

내보내기 예시(비어 있는 새 출력 경로 필요):

```powershell
.\.venv\Scripts\python.exe scripts\export_source.py --output outputs\NoseOut-github-source
```

생성된 폴더와 ZIP에는 Git 이력·환경·모델·엔진·사용자 설정·색인·로그·개인용 EXE를 넣지 않습니다.
`PUBLIC_SOURCE_MANIFEST.json`에 포함 파일의 SHA256과 기반 커밋을 기록합니다.
Windows TTS 시험 음성 네 개는 제외하고 생성 스크립트를 포함합니다.
개발 일지와 PC 사양이 담긴 내부 문서 `AGENTS.md`, `docs/progress.md`도 스냅샷에서 제외합니다(Git 작업 저장소에는 유지).
공개 문서가 이 두 파일을 링크하면 내보내기가 중단됩니다. Git 이력 자체를 공개하는 경우에는 이 두 파일이 이력에
남아 있으므로, 저장소를 올리기 전에 포함 여부를 따로 결정해야 합니다.

## GitHub 저장소 입력값 초안

- 이름: `NoseOut` (기존 프로젝트나 저장소 소유권은 생성 직전에 확인)
- 설명: `Windows 11용 로컬 파일 검색 — NTFS 이름 검색과 문서·이미지·음성·영상 AI 내용 검색`
- 토픽 후보: `windows`, `file-search`, `local-ai`, `semantic-search`, `python`, `pyside6`, `ntfs`
- 라이선스: 저장소의 MIT 전문과 원작자 고지를 그대로 유지
- 소스는 저장소에, 별도 공개용 실행 파일과 대응 소스 ZIP은 Releases에 함께 게시

## 실행과 데이터 범위

이름 검색은 선택한 범위의 이름·경로만 등록하고 AI 엔진 없이 동작합니다. AI 내용 분석은 별도로 고른
폴더·파일만 대상으로 합니다. NTFS 빠른 등록 때만 관리자 도우미가 볼륨 메타데이터를 읽고,
후속 변경은 일반 권한 USN으로 반영합니다. 처음 실행한 앱을 관리자 권한으로 상시 실행할 필요는 없습니다.

설정·색인은 `%LOCALAPPDATA%\NoseOut`에 보존됩니다(이전 이름 `DigUpWin` 폴더는 첫 실행 때 복사하고 남김). 원래 사용자 파일은 수정·삭제하지 않습니다.
이름 색인에도 파일 경로가 들어 있으므로 DB나 로그를 이슈 첨부물로 올리지 마세요.

## 검증 기록과 한계

- 기존 개발 환경 전체 테스트: 378개 통과(2026-10-15 개발 기록). 이후 재실행에서 동시 색인 시험 1개가 간헐적으로
  실패했다(이름 검색보다 AI 색인이 먼저 끝나는 고정 대기). 시험을 문(threading.Event)으로 바꿔 원인을 없앴다.
- 런타임 자동 준비·고지 정리 후 전체 테스트: 429개 통과(2026-10-15).
- 별도 EXE에서 실제 MFT 등록, 같은 볼륨의 범위별 등록 방식 보존, 재실행 후 변경 반영 확인.
- 공개용 EXE는 런타임 자동 준비를 넣어 다시 빌드했다. 복사본에서 별칭이 없는 상태로 실행해 앱 폴더(쓰기 가능)와
  사용자 설정 폴더(앱 폴더 쓰기 거부) 양쪽에서 별칭이 준비·로드되는 것을 확인했다(Qt offscreen).
- 모든 하드웨어·드라이브·권한 구성을 검증한 것은 아니며 Everything 수준의 성능을 주장하지 않습니다.
- 대응 모델·엔진이 없는 새 설치에서는 일부 테스트가 건너뛰어질 수 있습니다.

## 공개용 EXE 구성

기존 개인용 EXE는 그대로 보존합니다. 별도 `--public-candidate`에서 사용자 선택에 따라 HEIC 지원을 제외하고,
FFmpeg는 공식 다운로드 도구로 분리했습니다. 유효한 Visual Studio 재배포 사용권은 확인되지 않아 Microsoft 런타임 DLL도
동봉하지 않습니다. 사용자는 공식 VC++ x64 런타임을 설치한 뒤 `NoseOut.exe`(또는 `처음 실행.bat`)를 실행하며,
NumPy가 찾는 앱 내부 별칭은 EXE가 시작할 때 자동으로 준비합니다(앱 폴더에 쓸 수 없으면 사용자 설정 폴더).
인터넷에서 받은 `.ps1`은 실행 정책에 막히거나 더블클릭 시 메모장이 열리므로 필수 단계에서 뺐고,
`런타임 준비.ps1`은 수동 대안으로만 남겼습니다. Qt·Python·모델·엔진의 고지와 Qt·certifi의 대응 소스를 보완했습니다.
`licenses/Qt-6.12.0`은 `scripts/collect_qt_notices.py`의 필터로 고지 원문만 남겼습니다(예제·도구·설정 29개 제거,
누락됐던 PCRE2 `LICENCE.md` 추가). Gemma 상표 고지와 Gemma Prohibited Use Policy 안내를 README·제3자 고지에 두었습니다.
Releases 본문에는 README의 "Releases에서 받아 실행하기" 절과 각 ZIP의 SHA256을 함께 적습니다.
[공개용 배포 조건](binary-distribution.md)에 따라 **공개용 EXE ZIP과 대응 소스 ZIP을 함께** 올려야 합니다.
개인용 `outputs/NoseOut`이나 사용자가 의존성을 추가한 공개용 로컬 폴더를 대신 올리지 않습니다.
